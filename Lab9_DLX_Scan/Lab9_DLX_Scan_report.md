## Introduction

In Lab 8, we added output capability to our DLX processor via three print instructions (PCH, PD, PDU) that transmit characters and integers over UART to a serial terminal. The natural next step is to add input capability so the processor can consume data from the keyboard. In this lab, we add two new scan instructions — GD (0x34) for signed decimal input and GDU (0x35) for unsigned decimal input — that read an integer typed by the user on a serial terminal and store it into a destination register. This requires a UART receiver, an ASCII-to-integer conversion state machine, clock domain crossing FIFOs, and pipeline stall logic to pause execution until the user finishes typing.

## Procedure

### New Opcodes and Assembler Changes

Two new instructions were added to the instruction set:

| Instruction | Opcode | Format | Description |
|-------------|--------|--------|-------------|
| GD Rd | 0x34 | `Op[31:26] \| Rd[25:21] \| Unused[20:0]` | Get signed decimal integer from keyboard |
| GDU Rd | 0x35 | `Op[31:26] \| Rd[25:21] \| Unused[20:0]` | Get unsigned decimal integer from keyboard |

The assembler (`find_labels.c` and `Assembler.c`) was updated to recognize these mnemonics. The opcodes array was extended from 52 to 54 entries, and a new encoding case was added that places the destination register Rd at bits [25:21], similar to how PCH/PD/PDU encode their source register.

The opcode package (`decode_reg_pkg.vhd`) was updated with two new constants:

```vhdl
constant OP_GD    : std_logic_vector(5 downto 0) := "110100"; -- 0x34
constant OP_GDU   : std_logic_vector(5 downto 0) := "110101"; -- 0x35
```

### New Module: RX_UART (RX_UART.vhd)

This module was reused from Lab 1. It is a UART receiver with 8x oversampling that converts a serial bit stream into 8-bit bytes. It runs on the 153.6 kHz clock (8 times the 19200 baud rate) generated by the PLL. The receiver uses majority voting on the middle 4 samples of each bit period to determine the bit value, providing noise immunity. When a complete valid byte is received (start bit = 0, 8 data bits, stop bit = 1), it pulses `wrreq` for one cycle with the byte on `data_out`.

### New Module: Multiplication (multiplication.vhd)

This is a Quartus LPM_MULT IP block configured to multiply a 32-bit input by the constant 10. It has 8 pipeline stages to meet timing at 50 MHz. The input `dataa` is 32 bits wide, `datab` is hardcoded to the 4-bit constant "1010" (decimal 10), and the output `result` is 36 bits wide to prevent truncation. This multiplier is used by the ascii_to_int FSM for the `n = n * 10` accumulation step.

### New Module: ascii_to_int (ascii_to_int.vhd)

This is the core new module for Lab 9. It is a finite state machine that converts a stream of ASCII digit characters into a 32-bit integer. It runs at 50 MHz on the processor clock domain.

**Algorithm:** The FSM implements the standard string-to-integer conversion: `n = n * 10 + (digit - 48)`. Characters are read from the RX FIFO (which uses show-ahead mode, so the data is valid on `q` whenever `rdempty = '0'`). The FSM processes each character:

- **Digits ('0'-'9'):** Accumulate using the LPM_MULT multiplier (8-cycle wait for pipeline)
- **Minus sign ('-'):** Sets a negative flag if no digits have been seen yet (for signed GD)
- **Newline (0x0A) or Carriage Return (0x0D):** Terminates the integer, optionally negates if minus was seen, and asserts `scan_ready`
- **All other characters:** Ignored

The FSM has 6 states: `idle`, `read_char`, `process_char`, `wait_mult`, `add_digit`, and `done`. The conversion starts immediately when characters arrive in the RX FIFO — it does not wait for the processor to reach a GD/GDU instruction. This means the integer is typically already converted and waiting by the time the processor needs it.

The `done` state holds the result on `scan_data` with `scan_ready = '1'` until the processor asserts `scan_rdreq` to consume it, then resets and returns to `idle` for the next integer.

### Top-Level Wiring (Lab9_DLX_Scan.vhd)

The top-level entity was extended with the complete RX data path:

```
ARDUINO_IO(0) ← USB-TTL ← serial terminal (keyboard)
    → RX_UART (153.6 kHz, 8x oversampling)
    → dcfifo (8-bit, dual-clock: 153.6 kHz write / 50 MHz read)
    → ascii_to_int FSM (50 MHz)
    → scan_data / scan_ready / scan_rdreq → DLX_Processor
```

The existing FIFO component (Quartus dcfifo, 256-deep, 8-bit, show-ahead mode) was reused for the RX clock domain crossing. The RX_UART writes at 153.6 kHz and the ascii_to_int FSM reads at 50 MHz.

### Pipeline Integration (DLX_Processor.vhd)

Three new ports were added to `DLX_Processor`: `scan_data` (32-bit input), `scan_ready` (input), and `scan_rdreq` (output).

The scan stall logic uses a registered latch:

```vhdl
process(clk)
begin
    if rising_edge(clk) then
        if rst = '1' then
            scan_stalling <= '0';
        elsif scan_stalling = '0' and
              (internal_instr(31 downto 26) = OP_GD or
               internal_instr(31 downto 26) = OP_GDU) then
            scan_stalling <= '1';
        elsif scan_stalling = '1' and scan_ready = '1' then
            scan_stalling <= '0';
        end if;
    end if;
end process;

scan_stall <= scan_stalling;
```

When GD/GDU appears in the Fetch output (`internal_instr`), the registered `scan_stalling` flag latches high. This freezes the pipeline (Fetch holds, Decode inserts NOP bubbles) until `scan_ready` goes high, indicating the ascii_to_int FSM has a converted integer available.

The consume signal fires when GD/GDU reaches the Execute stage:

```vhdl
scan_rdreq <= '1' when (id_ex_opcode = OP_GD or id_ex_opcode = OP_GDU)
                       and scan_ready = '1' and flush = '0'
              else '0';
```

The hazard detection unit was also updated to mark GD/GDU as not reading any source registers (`uses_rs1 <= '0'`), preventing spurious load-use stalls.

### Execute Stage Changes (execute.vhd)

A `scan_data` input port was added, and the ALU output register input is muxed:

```vhdl
alu_or_scan <= scan_data when (opcode = OP_GD or opcode = OP_GDU)
               else ALU_out;
```

When a GD/GDU instruction passes through Execute, `scan_data` is latched into the ALU result register instead of the ALU output. This value then flows through Memory and Write-back normally — Write-back sees it as an ALU result and writes it to the destination register Rd. No changes were needed to the Memory or Write-back stages.

### Assembly Program

The factorial program was restructured to:

1. Print "Welcome to the DLX factorial program!" with CR+LF newline
2. Print "Enter a number: " prompt
3. Execute `GDU R1` to read the user's input
4. Echo the input with `PDU R1`
5. Compute the factorial using the existing multiply-by-repeated-addition subroutine
6. Print "N! = RESULT" with the input and factorial result
7. Loop back to `J end` (infinite loop; press reset to restart)

Proper CR+LF line endings were added (PCH with ASCII 10 for LF and ASCII 13 for CR) to ensure correct terminal display.

## Challenges and Solutions

- **Show-Ahead FIFO Timing:** The RX dcfifo uses show-ahead mode, meaning data appears on `q` immediately when `rdempty = '0'`, before `rdreq` is asserted. Our initial ascii_to_int FSM asserted `rdreq` before reading the data, causing it to skip the first character. The fix was to read the character directly from `rx_char` in the `idle` state (since it's already valid), process it in `process_char`, and assert `rdreq` during processing to advance to the next character.

- **Pipeline Stall Timing:** The synchronous ROM in the Fetch stage introduces a 1-cycle latency — by the time GDU appears on `internal_instr`, the PC has already advanced past it. A simple combinational stall on `internal_instr` would only last 1 cycle before Decode clears it to NOP. The solution was a registered `scan_stalling` latch that stays high until `scan_ready` arrives, freezing the pipeline for as long as needed.

- **Missing Pin Assignments:** When the Quartus project was restructured for Lab 9, the QSF file lost all `set_location_assignment` entries. This caused the FPGA to produce no output after programming. Adding back the DE10-Lite pin assignments for clocks, buttons, and Arduino header pins resolved this.

- **Factorial Off-By-One:** The original factorial loop set `count = value` before decrementing `value`, producing an incorrect multiplication count. Reordering the loop to decrement first (`SUBI R5, R5, 1`), then copy (`ADD R4, R5, R0`), then add 1 (`ADDI R4, R4, 1`) aligned the count with what the `f_multiply` subroutine expects, producing correct results.

## Results

The DLX processor with scan instructions is fully functional on the DE10-Lite FPGA. The program prompts the user for input, reads a decimal integer via UART, computes its factorial, and prints the result. Below is the serial terminal output from two consecutive runs:

```
Welcome to the DLX factorial program!
Enter a number: 4
4! = 24
Welcome to the DLX factorial program!
Enter a number: 20
20! = 2192834560
```

The program correctly computes 4! = 24. The result for 20! shows a 32-bit unsigned overflow (the true value is 2,432,902,008,176,640,000), which is expected behavior since our registers are 32 bits wide.

## Conclusion

In this lab, we successfully extended our custom DLX processor and assembler to support two new input instructions — GD (0x34) and GDU (0x35) — that read decimal integers from the keyboard via UART. The implementation required four new or reused hardware modules: the RX_UART receiver (from Lab 1), a dual-clock FIFO for crossing from the 153.6 kHz receive domain to the 50 MHz processor domain, an LPM_MULT IP core for multiply-by-10, and a custom ascii_to_int FSM that converts ASCII digit streams to 32-bit integers.

On the pipeline side, we added scan_data injection in the Execute stage (muxing scan_data onto the ALU result path for GD/GDU instructions) and a registered stall mechanism that freezes the pipeline until the user completes their input. The existing Write-back and Memory stages required no modification, as the scan data flows through the standard ALU result path.

The processor now supports full bidirectional UART communication: 5 I/O instructions (PCH, PD, PDU for output; GD, GDU for input) on top of the 49 original ALU, memory, branch, and jump instructions, for a total of 54 opcodes. The factorial demonstration program successfully reads user input, computes the factorial, and displays the result, meeting all pass-off requirements.

### ascii_to_int.vhd

```vhdl
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity ascii_to_int is
    port (
        clk        : in  std_logic;
        rst        : in  std_logic;
        rx_char    : in  std_logic_vector(7 downto 0);
        rx_empty   : in  std_logic;
        rx_rdreq   : out std_logic;
        scan_data  : out std_logic_vector(31 downto 0);
        scan_ready : out std_logic;
        scan_rdreq : in  std_logic
    );
end entity ascii_to_int;

architecture behavioral of ascii_to_int is
    type state_type is (idle, read_char, process_char, wait_mult, add_digit, done);
    signal state : state_type := idle;
    signal n           : unsigned(31 downto 0) := (others => '0');
    signal is_negative : std_logic := '0';
    signal has_digits  : std_logic := '0';
    signal saved_digit : unsigned(3 downto 0) := (others => '0');
    signal mult_count  : integer range 0 to 8 := 0;
    signal mult_in     : std_logic_vector(31 downto 0);
    signal mult_out    : std_logic_vector(35 downto 0);
    signal char_val    : unsigned(3 downto 0);
    signal is_digit    : std_logic;
    signal is_newline  : std_logic;
    signal is_minus    : std_logic;
begin
    char_val   <= unsigned(rx_char(3 downto 0));
    is_digit   <= '1' when rx_char >= x"30" and rx_char <= x"39" else '0';
    is_newline <= '1' when rx_char = x"0A" or rx_char = x"0D" else '0';
    is_minus   <= '1' when rx_char = x"2D" else '0';
    mult_in <= std_logic_vector(n);

    mult_inst : entity work.multiplication
        port map (clock => clk, dataa => mult_in, result => mult_out);

    process (clk)
    begin
        if rising_edge(clk) then
            if rst = '1' then
                state <= idle; n <= (others => '0'); is_negative <= '0';
                has_digits <= '0'; saved_digit <= (others => '0');
                mult_count <= 0; scan_ready <= '0'; rx_rdreq <= '0';
            else
                rx_rdreq <= '0';
                case state is
                    when idle =>
                        if rx_empty = '0' then state <= process_char; end if;
                    when read_char =>
                        rx_rdreq <= '0'; state <= idle;
                    when process_char =>
                        rx_rdreq <= '1';
                        if is_newline = '1' then
                            if has_digits = '1' then
                                if is_negative = '1' then
                                    scan_data <= std_logic_vector(-signed(n));
                                else scan_data <= std_logic_vector(n); end if;
                                scan_ready <= '1'; state <= done;
                            else state <= read_char; end if;
                        elsif is_digit = '1' then
                            saved_digit <= char_val; has_digits <= '1';
                            mult_count <= 0; state <= wait_mult;
                        elsif is_minus = '1' and has_digits = '0' then
                            is_negative <= '1'; state <= read_char;
                        else state <= read_char; end if;
                    when wait_mult =>
                        if mult_count < 8 then mult_count <= mult_count + 1;
                        else state <= add_digit; end if;
                    when add_digit =>
                        n <= unsigned(mult_out(31 downto 0)) + resize(saved_digit, 32);
                        state <= idle;
                    when done =>
                        if scan_rdreq = '1' then
                            scan_ready <= '0'; n <= (others => '0');
                            is_negative <= '0'; has_digits <= '0'; state <= idle;
                        end if;
                end case;
            end if;
        end if;
    end process;
end behavioral;
```

### DLX Assembly Program (Factorial_Assemble_Print.dlx)

```asm
.data
f   1   0
.const
s1 37 "Welcome to the DLX factorial program!"
s2 16 "Enter a number: "
s3 4 "! = "

.text
; Print welcome message (37 chars via PCH loop)
        ADDI R6, R0, 0
        ...4 NOPs...
        ADDI R7, R0, 0
        ...
        ADDI R8, R0, 37
        ...
        ADDI R20, R0, 10           ; LF character
        ...
        ADDI R21, R0, 13           ; CR character
        ...
titleloop
        SGEU R15, R7, R8
        ... BNEZ R15, titleend ...
        LW R10, s1(R6)
        ... ADDI R6, R6, 1 ... ADDI R7, R7, 1 ...
        PCH R10
        ... J titleloop ...

titleend
        PCH R20                    ; print LF
        ... PCH R21 ...            ; print CR

; Print "Enter a number: " (16 chars via PCH loop)
        ... (same pattern as title loop using s2) ...

promptend
        GDU R1                     ; Read unsigned integer from keyboard
        ...
        PDU R1                     ; Echo user input
        ... PCH R20 ... PCH R21 ... ; CR+LF

; Compute factorial of R1
        ADD R5, R1, R0             ; value = n
        ... BEQZ R5, onecase ...   ; 0! = 1
        SUBI R5, R5, 1             ; value = n-1
        ... BEQZ R5, onecase ...   ; 1! = 1
        ADD R3, R1, R0             ; result = n
loop1
        SUBI R5, R5, 1             ; value--
        ADD  R4, R5, R0            ; count = value
        ADDI R4, R4, 1             ; count adjustment
        ... BEQZ R5, done ...
        ADD R2, R3, R0             ; hold = result
        JAL f_multiply             ; result *= count
        ... J loop1 ...

f_multiply
        ADD R3, R3, R2             ; result += hold
        SUBI R4, R4, 2
        ... BNEZ R4, fix ...
        JR R31
fix     ADDI R4, R4, 1
        J f_multiply

onecase ADDI R3, R0, 1
        J done

; Print "N! = RESULT"
done    PDU R1                     ; print N
        ... (PCH loop for "! = " using s3) ...
        PDU R3                     ; print factorial result
        ... PCH R20 ... PCH R21 ... ; CR+LF

end     J end
```
